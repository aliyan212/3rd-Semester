## 1. Fundamentals of FSMs

A Finite State Machine (FSM) is a mathematical model of computation used to design both computer programs and sequential logic circuits. It is conceived as an abstract machine that can be in exactly one of a finite number of states at any given time, transitioning between them based on inputs.

### Combinational vs. Sequential Circuits

- **Combinational Circuit:** The output depends only on the current inputs present at that exact moment. They have no memory of past inputs (e.g., MUXs, Adders).
- **Sequential Circuit:** The output depends on both the current input and the past history of inputs. They require memory elements to store the current state (e.g., Flip-Flops, Registers).

### Basic Components of an FSM

1. **State:** Represents a specific condition or situation of the system based on its history.
2. **Input:** The external signal or data that is fed into the machine and triggers transitions.
3. **Output:** The response that is generated by the machine.
4. **Clock:** A timing signal used in Synchronous FSMs to coordinate state transitions at discrete intervals.
5. **Memory Element:** Hardware components (like flip-flops) used to store the binary representation of the current state.
## 2. Moore vs. Mealy Machines

FSMs are categorized into two primary architectures based on how they calculate their outputs.

- **Moore Machine:** The output depends _only_ on the current state. There is no direct wire from the input to the output logic.
- ![[Moore Machine.png]]
- **Mealy Machine:** The output depends on _both_ the current state and the current input. There is a direct wire routing the input straight into the combinational output circuit.    
- ![[Mealey Machine.png]]

### Detailed Comparison Table

|**Feature**|**Moore Machine**|**Mealy Machine**|
|---|---|---|
|**Output Dependence**|Depends solely on the current state.|Depends on both the current state and the input.|
|**Number of States**|Generally requires more states.|Generally requires fewer states.|
|**Speed**|Slower; Outputs are delayed by a clock cycle.|Faster; Reaction times are immediate as inputs change.|
|**Stability**|Highly stable and immune to mid-cycle input glitches.|Less stable; prone to glitching if inputs change mid-cycle.|
|**Hardware Complexity**|Requires more states, but the output logic is simpler.|Requires fewer states, but combinational output logic is more complex.|

**Real-Life Applications:** Traffic Light Controllers, Vending Machines, Combination Locks.

## 4. FSM Conversions

### Converting Mealy to Moore

**Goal:** Eliminate input-dependent outputs to increase stability and eliminate mid-cycle glitches.

**Conversion Rules:**

1. Look at incoming arrows for every Mealy state.
2. If all incoming arrows to a state share the same output, move that output inside the state to make it a Moore state.
3. **State Splitting:** If the incoming arrows have conflicting outputs, you must split the state into two states (e.g., one for output `0` and one for output `1`).
4. Route the incoming arrows to the newly split states that match their specific output.
5. Copy all original outgoing paths to both of the newly split states.

**Example Used:** Sequence Detector for "101".

### Step 1: The Original Mealy Machine

In your example, the Mealy machine detects "101" (allowing overlaps).

Notice state `S1`. It has three incoming arrows:

1. From `S0` (Input 1): Output is `0`.
2. From `S1` (Input 1): Output is `0`.
3. From `S2` (Input 1): Output is `1` (The sequence is detected!).

![[101 Detector Mealy.png]]

### Step 2: State Splitting

Because `S1` receives two different outputs (`0` and `1`), we must split it into two new states to satisfy the Moore machine rules:

- **$S1_0$:** Handles transitions that output `0`.
- **$S1_1$:** Handles transitions that output `1`.

### Step 3: The Converted Moore Machine

We pull the outputs off the edges and put them inside the states. Then, we copy the original outgoing paths of `S1` to _both_ of our newly split states.

![[Converted 101 Moore.png]]

_(Notice how transitioning from $S1_1$ with an input of 1 goes to $S1_0$, because the original Mealy machine outputs a 0 for that specific loop).

### Converting Moore to Mealy

**Goal:** Compress the number of required states to save hardware space/costs, and increase the system's reaction speed by removing the clock-cycle delay.

**Conversion Rules:**

1. Identify the output associated with each Moore state.
2. Remove the output from inside the state.
3. Attach that output value to every incoming transition edge that points to that specific state.
4. **State Compression:** Once the outputs are on the edges, evaluate if any states have become entirely redundant (serving only to pass a signal). If so, remove them and route the transition directly to the next logical state.

**Example Used:** Sequence Detector for "110".
### Step 1: The Original Moore Machine

This is the machine we built earlier. The outputs are baked directly into the states.

![[110 Moore Machine.png]]
### Step 2: Moving Outputs to Edges

We take the output from each state and attach it to every arrow pointing _into_ that state.

- Arrows pointing to `S0`, `S1`, and `S2` get a `/0` appended.
    
- The arrow pointing from `S2` to `S3` gets a `/1` appended.
    

### Step 3: State Compression

Once the outputs are moved to the edges, state `S3` becomes entirely redundant. Its only purpose was to hold the `1` output. Once it fires, an input of `0` takes it to `S0`, and an input of `1` takes it to `S1`—which is exactly how `S0` behaves!

Therefore, we can delete `S3` entirely and route the transition from `S2` directly back to `S0`, bringing the `/1` output with it. As you correctly noted, converting to Mealy allows us to compress states, saving hardware space and costs.
