# DLD Prerequisites and Processor Architecture

> [!abstract] Overview
> This document covers the foundational number system conversions required for [[Assembly Language]], followed by the architecture of a [[Basic Microcomputer Design|basic microcomputer]]. It traces the path from the [[System Clock]] through the [[Instruction Execution Cycle]] and ends with [[Pipelining]] as a method for improving processor throughput.

---

## Base Conversions

> [!note] Why This Matters
> Assembly Language and machine code are expressed in binary, but humans read and write in decimal, octal, and hexadecimal for convenience. The correct conversion method depends on the base: decimal requires the weightage method, while octal and hexadecimal allow a faster direct substitution because they are both powers of 2.

### Decimal to Binary (Weightage Method)

Convert base-10 to base-2 by breaking the number into powers of 2. This is the only base among the three that *requires* this subtraction process, since decimal is not a power of 2.

> [!example] Step-by-Step: $(45)_{10}$
>
> 1. Write out the binary weights (powers of 2) from right to left, down to 1: `32  16  8  4  2  1`.
>
> 2. Does 32 fit into 45? Yes. Write `1` under 32. Subtract: $45 - 32 = 13$.
>
> 3. Does 16 fit into 13? No. Write `0` under 16.
>
> 4. Does 8 fit into 13? Yes. Write `1` under 8. Subtract: $13 - 8 = 5$.
>
> 5. Does 4 fit into 5? Yes. Write `1` under 4. Subtract: $5 - 4 = 1$.
>
> 6. Does 2 fit into 1? No. Write `0` under 2.
>
> 7. Does 1 fit into 1? Yes. Write `1` under 1. Subtract: $1 - 1 = 0$.
>
> 8. **Result:** Combine the bits in order: $(101101)_2$.

$$(256)_{10} = (100000000)_2$$

*since $256 = 2^8$ exactly, this one resolves in a single step.*

### Octal to Binary (Direct Substitution)

Convert each base-8 digit directly into a **3-bit** binary group.

> [!example] Step-by-Step: $(76)_{8}$
> 1. Treat 7 and 6 as two different number to perform weightage method on and solve 7:
> 
> 2. Write out the binary weights (powers of 2) from right to left, down to 1: `4  2  1`.
>
> 3. Does 4 fit into 7? Yes. Write `1` under 4. Subtract: $7 - 4 = 3$.
>
> 4. Does 2 fit into 3? Yes. Write `1` under 2. Subtract: $3 - 2 = 1$.
>
> 5. Does 1 fit into 1? Yes. Write `1` under 1. Subtract: $1 - 1 = 0$.
>
> 6. **Result:** Combine the bits in order: $7=(111)$
> 
> 7. Move to 6 after finding 7.
> 
> 8. Does 4 fit into 6? Yes. Write `1` under 4. Subtract: $6 - 4 = 2$.
>
> 9. Does 2 fit into 2? Yes. Write `1` under 2. Subtract: $2 - 2 = 0$.
>
> 10. Does 0 fit into 1? No. Write `0` under 1.
> 
>  11. Combine both to find  $(76)_{8}=(111110)_{2}$

### Hexadecimal to Binary (Direct Substitution)

Convert each base-16 digit directly into a **4-bit** binary group.

> [!example] Step-by-Step: $(A7)_{16}$
> 1. Treat A and 7 as two different numbers to perform weightage method on
> 
> 2. Solve A first and since its written as hexadecimal treat it as 10.
> 
> 3. Write out the binary weights (powers of 2) from right to left, down to 1: `8 4  2  1`.
>
> 4. Does 8 fit into 10? Yes. Write `1` under 8. Subtract: $10 - 8 = 2$.
>
> 5. Does 4 fit into 2? No. Write `0` under 2.
>
> 6. Does 2 fit into 2? Yes. Write `1` under 2. Subtract: $2 - 2 = 0$.
> 
> 7. Does 1 fit into 0? No. Write `0` under 1.
>
> 8. **Result:** Combine the bits in order: $A=(1010)$
> 
> 9. Move to 7 after finding A.
> 
> 10. Does 8 fit into 7? No. Write `0` under 8.
>
> 11. Does 4 fit into 7? Yes. Write `1` under 4. Subtract: $7 - 4 = 3$.
>
> 12. Does 2 fit into 3? Write `1` under 2. Subtract: $3 - 2 = 1$.
> 
> 13. Does 1 fit into 1? Write `1` under 1. Subtract: $1 - 1 = 0$.
> 
>  14. Combine both to find  $(A7)_{16}=(10100111)_{2}$

## Basic Microcomputer Design

A processor's architecture relies on specialized internal components that communicate with external hardware over **buses**.

### Core CPU Components

- **[[Control Unit]]** (CU): Coordinates the sequence of all execution steps.

- **[[Arithmetic Logic Unit]]** (ALU): Performs mathematical arithmetic and bitwise logical processing.

### System Buses

System buses are the physical pathways that move data across the motherboard.

| Bus Type | Function |
| --- | --- |
| **[[Data Bus]]** | Moves actual data between the CPU, Main Memory (RAM), and I/O Devices. |
| **[[Address Bus]]** | Transmits the address generated by the CPU to locate specific data. |
| **[[Control Bus]]** | Carries commands from the CPU indicating whether data should be read or written. |

## The System Clock

The [[System Clock]] serves as the metronome for the entire architecture.

- **Function**: It synchronizes all CPU and BUS operations. Clock pulses are explicitly used to trigger hardware events.

- **Machine Cycle**: A clock cycle measures the precise time required to complete a single operation.

- **Frequency**: The frequency ($f$) is mathematically defined as:

$$f = \frac{1}{t}$$

*where $t$ is the duration of one cycle.*

## The Instruction Execution Cycle

The [[Instruction Pointer]] / [[Program Counter]] (IP/PC) manages the CPU's stage sequence by   storing the memory address of the next instruction. The CPU repeatedly loops through five stages:

1. **Fetch**: The CPU pulls the upcoming instruction from memory and loads it into the [[Instruction Register]] (IR).

2. **Decode**: The [[Control Unit]] decodes the instruction to determine the operation to perform.

3. **Fetch Operands**: The CPU retrieves any required data variables (operands) needed for the calculation.

4. **Execute**: The [[Arithmetic Logic Unit|ALU]] processes the math or logic task.

5. **Store Output / Write**: The final result is written back to a register or memory location.

## Pipelining and Processor Efficiency

Execution is divided into discrete stages. How a CPU handles these stages determines its throughput.

### Non-Pipelined Processors

Process one instruction fully from *Fetch* to *Store* before starting the next. This sequential approach results in many wasted cycles where hardware sits idle.

![[Non-Pipelined Processor.png|600]]

### Multi-Stage Pipeline

Makes it possible for the processor to execute instructions in parallel by overlapping the execution stages. As one instruction enters *Decode*, the next enters *Fetch*. This creates far more efficient use of cycles and greater overall throughput.

![[Pipelined Processor.png|600]]

> [!example] Pipeline Cycle Formula
> $$k + (n - 1)$$
>
> - $k$ = number of pipeline stages
> - $n$ = number of instructions
>
> This gives the *total cycles*, not the cycles per instruction. The first instruction still takes $k$ cycles to fully complete — pipelining hides latency for later instructions, it does not eliminate the latency of any single one.
>
> **Worked Example:** For a 5-stage pipeline executing 2 instructions:
>
> $$5 + (2 - 1) = 6 \text{ total cycles}$$


## Pipelining and Wasted Cycles

Processors can use varying pipeline models. For example, a **6-stage model** may include: Fetch, Decode, Register Read, Fetch Operand, Execute, and Store/Write. Even with a well-designed pipeline, delays still happen.

> [!note] Wasted Cycles
> Clock cycles are wasted when one pipeline stage requires two or more cycles to complete a complex or long instruction. This breaks the "one instruction per cycle" ideal that pipelining aims for.

![[Wasted Cycles in Pipelined Processor.png|600]]

> [!example] Extended-Instruction Formula
> When *every* instruction requires an extra cycle in the bottleneck stage, the required cycle count becomes:
>
> $$k + (2n - 1)$$
>
> - $k$ = number of pipeline stages
> - $n$ = number of instructions
>
> **Worked Example:** For a 5-stage pipeline ($k=5$) processing 3 instructions ($n=3$):
>
> $$5 + (2(3) - 1) = 10 \text{ cycles}$$
>
> *Caveat: this assumes uniform stalling across all instructions. If only some instructions are long, calculate the added stall cycles individually instead of doubling $n$ across the board.*
